# evals/ — 사건 묶음 판정 평가 데이터

`event_judgments_arg283.json`은 ARG-283 검토 페이지의 묶음 128개(맞음 45 · 애매 28 · 틀림 55)를
로컬 DB `tech_items`의 문서 id로 옮긴 것이다. 문서 id + 판정만 담고 본문·제목·URL은 없다.

**모든 숫자는 Claude 판정 기준(미검증)이다.** 판정은 Claude가 내린 잠정 정답이며 사람이 확인하지 않았다.

**DB를 리셋하면 문서 id가 바뀌어 이 파일을 다시 매핑해야 한다.** 매핑이 깨지면 스크립트는
"분할에 없는 판정 문서"로 빠진 수를 보고한다.

## 형식

`labels`(ok/maybe/bad), `must_keep`(반드시 유지할 묶음 번호: 21 = Kimi K3 3곳, 25 = Navier-Stokes + TechCrunch),
`clusters[{n, label, doc_ids}]`.

## 지표

- 묶음이 아직 묶임 = 그 묶음 문서 중 2건 이상이 같은 그룹. 맞음 엄격 유지 = 전부 한 그룹.
- 틀린 비율 = 아직 묶인 틀림 / (아직 묶인 맞음 + 아직 묶인 틀림). 애매는 빼고 개수만 따로 본다.
  변경 없는 분할이면 55/100. 보조로 애매=틀림 비율도 낸다.
- 반드시 유지 = `must_keep` 각 번호의 엄격 유지 여부.

## 재현

```bash
uv run python scripts/eval_event_judgments.py --mode both
uv run python scripts/eval_event_judgments.py --mode both --join-threshold 0.60
uv run python scripts/eval_event_judgments.py --sweep 0,0.01,0.02   # 같은 출처 보정 세기 스윕
uv run python scripts/eval_event_judgments.py --sweep 0:0,0.03:0.5,0.03:1   # 세기:전액 간격(일) 스윕
```

모든 리포트는 전체 판정 숫자 아래에 **고르기 몫(홀수 번 묶음)**과 **채점 전용 몫(짝수 번 묶음)**을
따로 찍는다(ARG-299). 보정 값은 고르기 몫만 보고 고른다. 반드시 유지(#21·#25)는 몫과 상관없이 전체
리포트에서 확인한다.

DB는 읽기만 한다(끝에 rollback). 밤 모드의 이웃 조회에는 설정의 `window_days`/`candidate_k`를 그대로 넘긴다.
참고: `join_threshold`를 바꾸면 실효 γ(`effective_leiden_resolution`)도 함께 따라간다.

1. 반드시 유지 #21·#25가 **낮·밤 모두** 유지되는 값만 후보.

### 왜 0.0인가

(숫자는 2026-10-13 재측정 기준. 2026-10-11 표에서도 결론은 같았다.)

- 낮 엄격 유지 41/45 이상(기준 2)을 지키는 값은 0.001·0.002뿐이고, 그때 틀린 비율은 55.0% → 53.7%·53.2%로
  사실상 그대로다(기준 3의 "뚜렷이"에 못 미친다). 0.003부터는 낮 엄격 유지가 40/45 이하로 떨어진다.
- 틀린 비율이 눈에 띄게 줄기 시작하는 0.01~0.02(45.6%→39.7%)는 엄격 유지가 38/45→33/45(낮)로 깎여
  맞는 묶음을 같이 잃는다. 보정이 맞는 묶음과 틀린 묶음을 구별하지 못하고 같은 비율로 쪼개는 셈이다.
  0.05 이상에서는 #25(Navier–Stokes)까지 깨진다. 무릎은 없다(감소가 거의 선형).
- 플랫폼 도메인 쌍은 기준선에서도 1개뿐이라 이 지표로는 보정의 부작용도 이득도 판별되지 않는다.

**과적합 주의:** 같은 128개로 고르고 같은 128개로 채점한다. 판정은 Claude의 잠정 정답(미검증)이다.

## ARG-299 — 같은 출처 보정을 발행 간격에 비례시킨다 (2026-10-13, 코퍼스 1783건) — Claude 판정 기준(미검증)

일괄 감점(위 ARG-284)은 같은 회사가 **같은 소식**을 여러 번 쓴 글까지 떼어냈다. 판정 묶음 안의 같은 출처
쌍 296개를 보면, 맞는 묶음의 쌍은 발행 간격 중앙값 0일(90분위 0.14일 — 발표 글과 시스템 카드, 한꺼번에 낸
사례 글처럼 같은 시각에 나온다), 틀린 묶음의 쌍은 중앙값 0.85일이었다. 그래서 감점을 간격에 비례시킨다:

    같은 출처 쌍의 감점 = same_source_penalty × min(1, 발행 간격(일) / same_source_gap_days)

### 고른 방법과 기본값 0.05 : 4

**고르기 몫(홀수 번 묶음)만** 보고 골랐다. 규칙: 고르기 몫 틀린 비율이 가장 낮고, 고르기 몫 엄격 유지가 기준선(낮

- `min_names` 2~3은 전체 틀린 비율을 크게 줄이지만(낮 39.2% → 29~32%) #25가 깨지고(밤은 #21도) 엄격 유지가 낮
  41/45 → 34~38/45로 떨어진다. 이름이 2~3개뿐인 글 쌍까지 "다르다"로 읽어 맞는 묶음을 같이 가른다.
- `min_names` 4부터 #21·#25가 지켜진다(0.02·0.03은 밤 #21이 깨지고, 0.05 이상에서 낮·밤 모두 유지).

## ARG-307 — 애매한 짝은 로컬 LLM에게 "같은 발표인가"를 묻는다

점수가 [τ, 0.65)인 **같은 사이트** 짝에만 `gemma4:26b`(think 끔)로 `SAME`/`DIFFERENT`를 묻는다. `DIFFERENT`인 짝만
간선(과 합치기 평균)에서 빠지고 `SAME`은 아무것도 바꾸지 않는다 — 점수 함수는 그대로다. 판단은
`~/.local/state/argos/pair_checks.jsonl`에 (두 id·모델·프롬프트 버전·제목/요약 해시)로 남아 같은 짝을 두 번 묻지 않는다.
다른 사이트 짝은 묻지 않으므로 오병합 20건 중 사이트가 다른 3건 안팎은 의도적으로 남는다.

측정 명령(실제 Ollama를 쓴다 — 다른 모델이 VRAM을 쓰는 동안에는 돌리지 않는다):

```bash
uv run python scripts/eval_event_judgments.py --mode night --pair-check          # 같은 사이트, [0.55, 0.65)
uv run python scripts/eval_event_judgments.py --mode night --pair-check --pair-check-cross-source   # 비교용
```
